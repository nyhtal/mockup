# Bylaw changelog

Semver per R-PREC-05: major = a previously green site now fails a gate; minor = new rule with a new gate; patch = wording.

## 0.21.0 — 2026-10-23

Sound (owner, 2026-10-23: "add style guides on sound effects and usage and then implement it on the site. more things need sound effects, hover of links, opening dropdowns accordions etc. when things slide in and stuff make appropriate sounds"). New bylaw 20 (R-SND-01 to R-SND-11) is the style guide for sound: fifteen synthesised cues from one pentatonic scale (hover, press, popover, disclosure and dialog pairs, step, toggle pairs, slider detent, copy, submit, entrance breath), their recipes and loudness order, one sound per action, a three-voice mixer with rate limits, hover only for a resting mouse, keyboard focus silent, one breath per section as it slides in, reduced motion and the calm level silencing the ambient cues, and nothing before the first click or key press of a page. The synthesiser moves out of `enhance.js` into `engine/scripts/sound.js` (≤ 4608 B, its own budget in the `budget` gate), imported only while sound is on (switched on, or restored for the tab) or for a style-guide audition, so a visitor who never does downloads none of it; `enhance.js` shrinks. Pages carry the flair level as `data-motion` on `<html>`. The style guide's foundations page gains a Sound section with a Play button per cue. D62 supersedes D44's trigger list and D52's "motion stays silent". Also reverted: an unreviewed edit to `enhance.js` from a Grok consultation that had been swept into `3793475` (a sawtooth copy sound, a dialog-close sound, a quieter default gain); its cues are replaced by bylaw 20's. The default HTML budget rises to 75 KB (R-PERF-01) for the `data-motion` flag, which put the German pricing page 13 B over. Minor by R-PREC-05.

## 0.20.0 — 2026-10-23

One image format (owner, 2026-10-23: "get rid of the webp versions then, i dont want to support multiple images of the same thing"). R-HTML-12, R-PERF-05, R-ASSET-05/06 and D6: pictures are AVIF only, one file per width. The `picture` primitive now renders a plain `img` with the AVIF `srcset`, `sizes` and a 480 px AVIF `src`; the `<picture>` wrapper and its WebP source are gone. `build-images.js` encodes AVIF only (quality 42, effort 6, as before), and a page that still references a `.webp` image fails the build, naming the page. The sample clip's poster is `<slug>-poster.avif`, and the schema graph's `image` points at the 1200 px AVIF. The style guide's image-map demo (0.19.0) points at the AVIF. The reference build no longer writes any WebP file (it has 291 AVIF). Visitors download the same bytes as before, because every browser that could use AVIF already took it. A browser without AVIF (Safari 15 and older: iOS 15 and earlier, including the iPhone 6s, 7 and first SE) now shows no picture, only the alt text. The HTML element reference shows `<picture>` live, doing art direction (a wide crop from 768 px, square below), the one job left for it; `source` points at the landing page's clip. The art library's sources in `engine/art/` stay WebP: one master per piece, never served. The clip keeps MP4 and WebM. Minor by R-PREC-05: a rule changes, no gate is added, and a site green before stays green.
