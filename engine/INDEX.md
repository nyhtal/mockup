# Engine index: what to read for which task

Read the files in the order listed. Bylaws are numbered rule files in `bylaws/`; each rule has an ID like `R-HTML-04` that pages, decisions and reviews cite.

## Build a new site from a Site Brief

1. `README.md`, then `site-brief/TEMPLATE.md` (the brief's fields, their destination files and defaults); `../sites/reference/brief.md` is the filled-in example
2. `DESIGN.md` (the look and the motion language), then `DECISIONS.md` (engine-wide decisions D1–D34)
3. `bylaws/00-precedence.md`
4. `bylaws/09-pages.md` (inventory and tiers → which pages to create)
5. `bylaws/02-tokens.md` (brand inputs → `site.json`)
6. `bylaws/10-content.md` and `bylaws/11-i18n.md` (voice, locales, strings)
7. `bylaws/08-sections.md` (what each page is made of)
8. `checklists/new-site.md` (procedure, then every rule the checklist verifies; regenerate with `npm run checklists`)

## Where a site's content lives (D30)

- `sites/<name>/site.json`: name, locales, nav, footer, brand, contact; UI labels are keys.
- `sites/<name>/i18n/<locale>.json`: site-specific UI strings, merged over `engine/i18n/<locale>.json` (same keys in every locale).
- `sites/<name>/data/<locale>/entities.json`: services, products, industries, people, offices, jobs, events, downloads, posts, press, cases, docs, tags and the small lists (testimonials, customers, stats, faq groups, glossary…); same slugs in every locale.
- `sites/<name>/data/<locale>/pages.json`: `sections` (site section definitions, referenced by id from pages; `from: "<kind>"` expands entities into cards), `detail` (recipes that generate one page per entity: `each`, `layout`, `sections` with `{e.field}` placeholders), `thankYou`, `sitemap`, `feedTitle`.
- `sites/<name>/content/<locale>/*.md`: one front-matter file per singular page (`pageType`, `title`, `description`, `eyebrow`, `lede`, `sections`); legal pages carry their markdown body. No markup anywhere in a site.
- Engine code behind it: `tools/lib/site.js` (loading), `tools/lib/sections.js` (resolver), `tools/lib/entities.js` (cards and schema nodes), `tools/lib/markdown.js`, `tools/lib/sampling.js` (Lighthouse coverage), `catalog/virtual/{entity,thank-you,sitemap-page,feed}.njk`.

## Add a page to a site

1. `bylaws/09-pages.md` (its row: URL, title, sections, schema contract)
2. `bylaws/08-sections.md` (section order and limits)
3. `bylaws/12-seo-meta.md` and `bylaws/13-schema.md`
4. `bylaws/10-content.md` (lengths, wording)
5. `checklists/new-page.md`

## Add or change a catalog component

1. `DESIGN.md` §3–§4 (motion table, visual vocabulary), then `bylaws/07-components.md` (anatomy block, states, patterns)
2. `bylaws/01-html.md`, `bylaws/02-tokens.md`, `bylaws/03-layout.md`, `bylaws/04-typography.md`, `bylaws/05-color.md`, `bylaws/06-motion.md`
3. `bylaws/14-accessibility.md` and, for forms, `bylaws/16-forms.md`
4. `checklists/new-component.md`

## Add a locale

1. `bylaws/11-i18n.md`
2. `bylaws/03-layout.md` (R-LAY-04, R-LAY-08, R-LAY-09) and `bylaws/04-typography.md` (R-TYPO-05, R-TYPO-12)
3. `i18n/_template.json` → `i18n/<locale>.json`
4. `checklists/new-locale.md`

## Review or deliver a site

1. `bylaws/19-quality-gates.md`
2. `bylaws/15-performance.md`, `bylaws/17-assets.md`, `bylaws/18-security-deploy.md`
3. `checklists/pre-delivery.md`
4. `reports/latest.md` (the evidence)

## Deliver: the evidence

`reports/latest.md` is regenerated by every gate run and carries the gate table, the Lighthouse coverage table, page weights and the axe review list; the manual checks from `checklists/pre-delivery.md` are appended to it after the last gate run. `LICENSES.md` lists the third-party assets a build can ship.

## Change the bylaws

1. `bylaws/00-precedence.md` (R-PREC-03 to R-PREC-05)
2. `CHANGELOG.md`
3. `npm run checklists` (the bylaws gate fails when a rule is missing from its checklist)
4. Rebuild and gate the reference site in `sites/reference/`
