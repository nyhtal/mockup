# Mockup engine

A rulebook, a catalog and a build that turn a one-page Site Brief into a static, multi-locale corporate website mockup: Tailwind-only markup, no runtime JavaScript library, native overlays and disclosures, schema.org on every page, and nine quality gates (HTML validity, consistency, structured data, page weight, i18n, links, accessibility, Lighthouse). The reference site in `sites/reference/` is Northwind Dynamics, a fictional industrial-automation company, in English, German and Arabic.

## Prerequisites

Node 24, a local Chrome (for the accessibility and Lighthouse gates), and once per machine:

```bash
npm install
npm run setup
```

`npm run setup` downloads the pinned Nu HTML checker with its own Java runtime into `engine/tools/vnu/` (ignored by git).

## Commands

| Command | What it does |
|---|---|
| `npm run build -- --site <name>` | Builds `sites/<name>/` into `dist/<name>/`: Eleventy pages, locale coverage check, fonts (script faces subset), icon sprites, the theme with the brand tokens, Tailwind, placeholder images, favicons, social images. |
| `npm run gate -- --site <name>` | Runs the nine gates against `dist/<name>/` and writes `reports/latest.md`. `--skip lighthouse` while iterating (Lighthouse takes hours on a large site), `--only <gate,gate>` for one gate, `--runs <n>` to change the Lighthouse run count. |
| `npm run serve -- --site <name>` | Serves `dist/<name>/` on http://127.0.0.1:8080 with the production cache headers and gzip. |
| `npm test` | The engine's unit tests (`engine/tools/test/`); the browser-driven gate tests need `SMOKE=1` and a built site. |
| `npm run checklists` | Regenerates `engine/checklists/*.md` from the bylaws; the bylaws gate fails when they are out of date. |

The gate exits non-zero on any finding. Every gate but Lighthouse runs on every page; Lighthouse measures every page in the default locale and one page per page type in each other locale, and the report lists which URL stood for each type.

## Repository layout

```
engine/
  bylaws/            00–19: the rules, each with an ID, MUST/SHOULD, Why and the gate that checks it
  catalog/           Nunjucks macros: primitives, components, sections, templates, virtual pages
  checklists/        generated from the bylaws (+ _preambles/ with the hand-written procedures)
  i18n/              engine UI strings per locale (_template.json lists every key)
  site-brief/        TEMPLATE.md, the one-page brief a site starts from
  theme/app.css      the Tailwind input: @theme tokens, keyframes, custom variants, the CSS exception list
  tools/             build, gate, serve, setup; gates/ one module per gate; lib/ shared code; test/
  budgets.json  schema-contracts.json  icons.json  LICENSES.md
  DECISIONS.md  CHANGELOG.md  INDEX.md
sites/<name>/
  brief.md  site.json  DECISIONS.md  glossary.json
  i18n/<locale>.json              site strings merged over the engine's
  data/<locale>/entities.json     services, products, people, jobs, events, posts, … (same slugs in every locale)
  data/<locale>/pages.json        site section definitions, detail-page recipes, thank-you pages, site map
  content/<locale>/*.md           one front-matter file per singular page; legal pages carry markdown bodies
dist/<name>/                      the deliverable (gitignored)
reports/latest.md                 the last gate report
```

## How a brief becomes a site

1. Fill `engine/site-brief/TEMPLATE.md`; every field names the file and key it lands in. Save it as `sites/<name>/brief.md`.
2. Create `site.json`, the string overlays, the data files and the singular pages as `engine/checklists/new-site.md` walks through them. Pages contain data only; every piece of markup comes from the catalog.
3. Detail pages (one per service, person, job, post, …) are generated by the engine from `pages.json` `detail` recipes: `each` names the entity kind, `sections` composes catalog sections with `{e.field}` placeholders and `from: "e.<list>"` expansions. Thank-you pages, the HTML site map and the Atom feed are generated too.
4. `npm run build` and `npm run gate -- --skip lighthouse` until green; fix findings in the data. Then the full gate, the manual checks in `engine/checklists/pre-delivery.md`, and the report committed.

## The bylaws

`engine/bylaws/` is the binding rulebook: 274 rules across 20 files, each a `### R-AREA-NN Title` heading with a MUST or SHOULD sentence, a reason and the gate check or checklist that verifies it. Precedence between rules, how a site may override one (an entry in its `DECISIONS.md`) and how the rulebook is versioned are in `bylaws/00-precedence.md`; engine-wide decisions are numbered in `engine/DECISIONS.md`. A change to the bylaws bumps `CHANGELOG.md` and rebuilds and gates the reference site.

`engine/INDEX.md` gives the reading order for the common tasks: build a new site, add a page, add a component, add a locale, deliver.
