# 11 Internationalisation

Purpose: every site is multi-locale from the first commit: folder layout, language tags, alternates, direction, formatting and the switcher. Sources: https://developers.google.com/search/docs/specialty/international/localized-versions, https://www.11ty.dev/docs/plugins/i18n/, Unicode CLDR, W3C i18n "Language on the web" and RTL guidance.

### R-I18N-01 Folder per locale
MUST. Content lives in `sites/<name>/content/<locale>/…` and builds to `/<locale>/…`. Every page that exists in the default locale exists in every other locale; the build fails otherwise.
Why: Partial locales produce dead links and broken hreflang.
Gate: i18n/hreflang-target

### R-I18N-02 BCP 47 tags
MUST. Locale codes are BCP 47 (`en`, `de`, `ar`, `pt-BR`, `zh-Hans`) in folder names, `lang` attributes, `hreflang` values and `inLanguage` schema fields.
Why: Every consumer (browser, crawler, screen reader) expects the same tag.
Gate: i18n/lang-attr

### R-I18N-03 Direction
MUST. `<html dir>` is `rtl` for locales listed in `site.json` `rtl` (default `ar`, `he`, `fa`, `ur`) and `ltr` otherwise. Layout uses logical properties (R-LAY-04); only directional icons use the `rtl:` variant.
Why: Direction is a document property, not a stylesheet.
Gate: manual: checklists/new-locale.md

### R-I18N-04 Reciprocal hreflang with x-default
MUST. Every page lists an alternate for every locale including itself plus `x-default` pointing at the default locale; each alternate page lists the same set.
Why: Google ignores non-reciprocal alternates.
Gate: i18n/hreflang-reciprocal

### R-I18N-05 UI strings only through `t`
MUST. Templates obtain UI strings with `{{ "key.path" | t }}`; a missing key fails the build. Content copy lives in the locale's content files, never in templates.
Why: Untranslated strings should be impossible, not merely unlikely.
Gate: i18n/keys

### R-I18N-06 No string assembly
MUST. Strings are never concatenated from fragments or built with placeholders that change word order; each sentence is one key or one content field. Plural forms are separate keys (`jobs.count.one`, `jobs.count.other`) chosen at build time.
Why: Word order and plural rules differ per language.
Gate: manual: checklists/new-locale.md

### R-I18N-07 Formatting at build time
MUST. Dates, numbers, currencies and units are formatted at build time with `Intl` for the page's locale (`en` 17 October 2026, `de` 17. Oktober 2026, `ar` 17 أكتوبر 2026, `ja` 2026年10月17日; digits are Latin for every locale unless `site.json` `numberingSystem` opts a locale into its native digits, e.g. `arab`). No formatting in the browser.
Why: Correct per locale and zero shipped JS.
Gate: manual: checklists/new-locale.md

### R-I18N-08 Locale switcher
MUST. The switcher is a popover listing every locale by its native name (`Deutsch`, `العربية`, `日本語`) with `lang` and `hreflang` on each link, never flags, and links to the same page in the other locale.
Why: Flags are countries, not languages; same-page switching keeps context.
Gate: manual: checklists/new-locale.md

### R-I18N-09 Translated slugs
MUST. When the brief asks for translated slugs, `site.json` `slugs` maps each default slug to its locale slug; the i18n alternates and sitemap use the mapped URLs. Otherwise slugs are shared.
Why: Localised URLs help search in that language but must stay consistent with alternates.
Gate: i18n/hreflang-reciprocal

### R-I18N-10 Text expansion
MUST. Layouts and limits assume 135 % of the English length (R-LAY-09, R-CONT-13); a locale that still overflows is fixed in the catalog, not by shortening the translation.
Why: Design for the longest language, not the source.
Gate: manual: checklists/new-locale.md

### R-I18N-11 Fonts per script
MUST. Each locale's script has a font in the approved list (R-TYPO-01, R-TYPO-12), or for Japanese the platform's own faces (D58); the build ships only the subsets its locales need and preloads only the page's primary script. The locale switcher's native language names are set in the system font (`font-system`) so a page never downloads another script's face for one word.
Why: Glyph coverage without shipping every script to every page.
Gate: manual: checklists/new-locale.md

### R-I18N-12 Fallback is an error
MUST. There is no silent fallback to the default locale for a missing page, string or image caption. Missing content fails the build with the path named.
Why: A German page with English paragraphs is worse than no German page.
Gate: i18n/keys

### R-I18N-13 Region-specific pages
MUST. Pages required by law in some regions (imprint for `de`/`at`, UK modern slavery statement) exist in those locales and are absent elsewhere; the inventory marks them "locale-specific" and the coverage check exempts them via `site.json` `localeOnly`.
Why: Legal pages are per jurisdiction, not per language.
Gate: manual: checklists/new-locale.md

### R-I18N-14 Addresses, phones, names
MUST. Postal addresses follow the office country's format; phone numbers are in international format (`+49 30 1234567`); personal names are not split into first/last fields in forms (one "Full name" field).
Why: Formats that assume one country break for every other.
Gate: manual: checklists/new-locale.md

### R-I18N-15 Sitemap alternates
MUST. `sitemap.xml` lists each page once per locale with `xhtml:link rel="alternate" hreflang` entries mirroring the page's head.
Why: Google reads alternates from either place; they must agree.
Gate: manual: checklists/pre-delivery.md

### R-I18N-16 Images and culture
SHOULD. Generated placeholder imagery is abstract so no locale receives culturally specific scenes; when a brief supplies real imagery, each locale may override it per page.
Why: Imagery carries meaning across cultures that copy cannot fix.
Gate: manual: checklists/new-locale.md
