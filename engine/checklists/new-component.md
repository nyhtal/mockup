# New component checklist

Use this for a new primitive, component or section in `engine/catalog/`, and for a new variant of an existing one. A page may not carry markup of its own (R-PREC-06), so a need no component covers ends here.

## Procedure

1. **Decide the layer**: primitive (one element and its states), component (a reusable block with a `data-component` root), section (a `<section>` with a `shell`, exported as `render(s, ctx)` and added to `sections/_render.njk`).
2. **Write the anatomy block first** (R-COMP-01): name, purpose, anatomy, variants, states, spacing, motion, keyboard, a11y, i18n, content limits, data. The data line is the contract pages and recipes use.
3. **Compose from existing layers** (button, field, icon, picture, card, shell, `cardGrid`, `formBody`); import macros `with context` so the `t` filter knows the page's language, and never name a macro argument like a page variable (`items`, `e`, `lang`, `title`, `content`).
4. **Classes**: Tailwind utilities only, logical properties for direction (`ps-`, `ms-`, `start-`, `text-start`), `motion-safe:` on every transition and animation, the focus-ring triple on every interactive element, `rtl:-scale-x-100` on directional icons, no arbitrary lengths, no palette colours (role tokens only).
5. **UI strings** through `t` with keys added to `engine/i18n/_template.json` and every engine locale file; plural strings as objects of CLDR forms.
6. **Add a sample** to `engine/catalog/samples.json` (sections) or to the style-guide page for the layer, so the style guide and the consistency gate exercise it.
7. **Build the reference site and gate** with `--skip lighthouse`; then open the style-guide page and one real page using it at 320 px, 1024 px and 1280 px, in an RTL locale too.
8. **Budget**: a section used on every page costs its markup times the page count; check the home page's HTML size in `reports/latest.md`.

## Learned on the reference site

- Text inside an SVG (wordmarks, logo clouds) is an axe "needs review" contrast item on every page; keep it on role colours the theme's contrast check already covers and note it under the review list.
- A section without a visible title needs `label` so the shell gives it `aria-label`; a heading inside it must be an `h2`, not an `h3`.
- `display: contents` on `<details>` slots its children into `::details-content`; style the panel through the `details-content:` variant.

## Rules this checklist verifies

Generated by `npm run checklists` from every rule whose `Gate:` line names `checklists/new-component.md`; edit the bylaws or the preamble in `_preambles/`, not this list. Tick each item or record the override in the site's `DECISIONS.md` (R-PREC-02; tier-1 rules cannot be overridden).

### 01 HTML

- [ ] **R-HTML-08** Allowed ARIA — ARIA attributes are limited to: `aria-label` on `nav`, `section` without visible heading text and icon-only buttons; `aria-current="page"` on the active nav link; `aria-describedby` linking an input to its help or error text; `aria-hidden="true"` on decorative SVG; `aria-live="polite"` on toast and status regions; `aria-expanded` only where the Popover API cannot express the state. Anything else needs a DECISIONS entry.
- [ ] **R-HTML-13** Inline SVG icons — Icons are `<svg aria-hidden="true" class="size-5 ..."><use href="#i-<name>"></use></svg>` from the sprite, next to visible text or, in icon-only controls, an `sr-only` label.

### 02 Tokens

- [ ] **R-TOK-02** Rhythm steps — Vertical spacing between blocks uses only these steps: 2, 4, 6, 8, 12, 16, 24, 32 (`space-y-*`, `gap-*`, `mt-*`, `py-*`). Inside a component, 1, 3 and 5 are also allowed for fine alignment (button padding is `px-5`).
- [ ] **R-TOK-04** Colour roles, not hues — Pages use only role colours: `brand-50…950`, `accent-50…950`, `surface`, `surface-alt`, `surface-raised`, `ink`, `ink-muted`, `ink-brand`, `ink-inverse`, `line`, `line-strong`, `focus`, `success`, `warning`, `danger` (each state colour with `-soft` and `-strong`). Tailwind's named palettes (`gray-900`, `blue-500`) are not used in pages.
- [ ] **R-TOK-05** Roles carry both schemes — Every role token is defined with `light-dark(<light>, <dark>)` and `<html>` carries `scheme-light-dark`. Pages never use the `dark:` variant. Fallback: browsers older than Chrome 123, Safari 17.5 or Firefox 120 (all before mid-2024) ignore `light-dark()` and render the browser's default colours (black text, transparent backgrounds), which stays readable; `light-dark()` becomes Baseline Widely available on 2026-11-13. This overrides spec §4.4 (recorded in DECISIONS D7).
- [ ] **R-TOK-07** Radius presets — `--radius-sm|md|lg|xl|full` take one of three presets chosen in the brief: `sharp` (0, 0, 0, 0, 9999px), `soft` (0.25rem, 0.5rem, 0.75rem, 1rem, 9999px), `round` (0.5rem, 1rem, 1.5rem, 2rem, 9999px). Components use `rounded-md` for controls, `rounded-lg` for cards, `rounded-xl` for hero media, `rounded-full` for avatars and pills.
- [ ] **R-TOK-08** Shadows — Only `shadow-sm` (cards at rest), `shadow-md` (cards on hover, dropdowns) and `shadow-lg` (dialogs, drawers) exist; `shadow-xl`, `shadow-2xl` and coloured shadows are not used.
- [ ] **R-TOK-09** Z-index scale — `z-10` sticky header and sub-nav, `z-50` toasts. No other `z-*` is used: dropdowns, menus, drawers, tooltips and dialogs are popovers or dialogs (R-COMP-09), which live in the top layer and carry no `z-*`.
- [ ] **R-TOK-10** Breakpoints and container — Breakpoints are Tailwind defaults (`sm` 40rem, `md` 48rem, `lg` 64rem, `xl` 80rem). The page container is exactly `mx-auto w-full max-w-7xl px-4 sm:px-6 lg:px-8`; prose measure is `max-w-prose`.
- [ ] **R-TOK-11** Durations and easings — Durations are `duration-150` (hover, focus, press), `duration-200` (dropdown, popover, drawer), `duration-300` (dialog, page transition), `duration-(--reveal-duration)` (entrances, set by the flair dial in R-TOK-12) and `duration-1200` (the picture settle and the timeline rule, which travel further). Easings are `ease-out` for overlays, `ease-in-out` for movement, `ease-reveal` (`--ease-reveal: cubic-bezier(0.16, 1, 0.3, 1)`, an exponential ease-out: fast away, long settle) for every entrance, `ease-spring` (`--ease-spring: cubic-bezier(0.34, 1.56, 0.64, 1)`, a slight overshoot) for the icon pop only, and `--ease-smooth` for the scroll-driven conveniences of R-MOT-14.

### 03 Layout

- [ ] **R-LAY-01** One container — Every section's content sits in the container from R-TOK-10. Full-bleed backgrounds wrap the container; content never touches the viewport edge.
- [ ] **R-LAY-03** Grids — Multi-column layouts use `grid` with `gap-6 md:gap-8` and only these column sets: `md:grid-cols-2`, `md:grid-cols-3`, `md:grid-cols-2 lg:grid-cols-4`, or the 12-column `lg:grid-cols-12` with `col-span-*` for asymmetric splits (the hero's text five, media seven). Items stack to one column below `md`, except tile grids: short tiles (team, integrations, awards, stats, logos) use `grid-cols-2 gap-4 md:gap-8 lg:grid-cols-4` and sit two across from 320 px, with cards at `p-4 md:p-6`. Descriptive cards (services, products, industries, cases, articles, jobs, offices, downloads, events, help, values, benefits, pricing, testimonials, forms) never go two across on a phone.
- [ ] **R-LAY-06** Measure — Running text is limited to `max-w-prose` (65ch); ledes to `max-w-2xl`; headings to `max-w-3xl`. Centred intro blocks use `mx-auto` with those limits.

### 04 Typography

- [ ] **R-TYPO-03** Weights — Only `font-normal` (400), `font-medium` (500), `font-semibold` (600) and `font-bold` (700) are used. Headings are semibold or bold; body is normal; labels and nav are medium.
- [ ] **R-TYPO-04** Element scale — Text elements use exactly these classes: h1 `text-4xl md:text-5xl font-bold tracking-tight text-balance` (in a hero, `xl:text-6xl` as well, except German pages, which stay at `text-5xl` through `xl:[&:lang(de)]:text-5xl` because their compounds would break mid-word); h2 `text-3xl md:text-4xl font-semibold tracking-tight text-balance`; h3 `text-xl md:text-2xl font-semibold`; h4 `text-lg font-semibold`; eyebrow `text-sm font-medium uppercase tracking-wide text-ink-brand`; lede `text-lg md:text-xl text-ink-muted`; body `text-base leading-relaxed`; small `text-sm text-ink-muted`; stat value `text-4xl font-bold tabular-nums` (`text-3xl sm:text-4xl md:text-5xl lg:text-6xl` on the stats band, where two columns from 320 px must hold a non-wrapping eight-character value such as the German "99,98 %"); hero proof figure `text-xl md:text-2xl font-semibold tabular-nums whitespace-nowrap`.
- [ ] **R-TYPO-06** Balance, not pretty — `text-balance` is used on h1, h2 and ledes only; `text-pretty` is not used (limited availability).
- [ ] **R-TYPO-09** Numbers — Figures in stats, tables and pricing use `tabular-nums`; locale formatting is done at build time (bylaw 11), never via JS. The count-up of R-MOT-10 renders its intermediate frames with `Intl.NumberFormat` in the page's language with Latin digits and ends by restoring the build-time text exactly, so the figure a reader keeps is the one the build wrote.
- [ ] **R-TYPO-10** Prose component — Article bodies are rendered through the `prose` catalog component, which applies the element scale to markdown output via child selectors in the utility list (`[&_h2]:…`). No `@tailwindcss/typography` plugin.

### 05 Colour

- [ ] **R-COL-01** Role usage — Backgrounds use `bg-surface` (page), `bg-surface-alt` (alternate sections), `bg-surface-raised` (cards, popovers, dialogs). Text uses `text-ink` (body, headings), `text-ink-muted` (secondary), `text-ink-brand` (eyebrows, links and icons in the brand colour on surfaces), `text-ink-inverse` (on brand backgrounds and dark media; it is the same light value in both schemes because brand backgrounds do not change with the scheme). Borders use `border-line` and `border-line-strong` for inputs. Primary actions use `bg-brand-600 text-ink-inverse hover:bg-brand-700`; secondary actions use `border-line-strong text-ink hover:bg-surface-alt`.
- [ ] **R-COL-02** Accent is rare — Accent means evidence (DESIGN.md §1). `accent-*` appears only in: the eyebrow marker rule, the marker under a case-study metric, the far end of the stats band's numeral gradient (`to-accent-200`), the hero's second glow, the far end of the CTA panel gradient and the footer hairline. It is never a button background, an icon tile or a text colour. Brand means identity and action (the mark, buttons, links, icon tiles, markers on timelines and steps); state colours mean state and never decorate (an icon tile is never `success`).
- [ ] **R-COL-05** State colours only for states — `success`, `warning`, `danger` appear only in form feedback, alerts, badges and toasts. `danger-strong` text on `danger-soft` background, and so on, are the only pairings.
- [ ] **R-COL-07** Dark scheme is automatic — No `dark:` classes in pages. Role tokens contain both values (R-TOK-05); media that cannot adapt gets a `bg-surface-raised` frame; shadows stay, and `line` gets lighter in dark mode via its token. The scheme follows the system until the visitor uses the theme toggle (header from `xl`, drawer, footer): the toggle sets `data-theme` on `<html>`, which switches `color-scheme` (`data-[theme=light]:scheme-light`, `data-[theme=dark]:scheme-dark`), so every `light-dark()` token follows with no other change (D54).
- [ ] **R-COL-08** Text over media — Text over images or video facades sits on a `bg-ink/60` overlay (or a `from-ink/70` gradient) and uses `text-ink-inverse`; the overlay is part of the component, never optional.
- [ ] **R-COL-09** Gradients — Gradients appear only as: the hero glow (two radial gradients, brand behind the text and accent behind the media at ≤ 40 % alpha, no texture), the CTA panel (`bg-linear-to-br from-brand-700 via-brand-600 to-accent-600`), the stats band numerals (`from-ink-inverse to-accent-200` clipped to text, with `text-ink-inverse` as the fallback colour) the footer hairline (`from-brand-600 to-accent-600`, one pixel), in `expressive` the stats band's depth layer (`from-brand-800/70 via-brand-700/0 to-accent-600/25`, behind the band) the light art scrim (`bg-art-scrim-light`: the same band in the page surface, for the light backdrop) and the art scrim (`bg-art-scrim`: brand-950 over the art behind the text of the `backdrop` hero and the `banner` page header; below `lg` 62 → 90 % from top to bottom, from `lg` an eased side band 88 % → 74 % at 30 % → 45 % at 50 % → 16 % at 68 % → clear at 84 %, mirrored in RTL). No other text gradients.

### 06 Motion

- [ ] **R-MOT-01** Compositor properties only — Animations and transitions change only `opacity`, `transform`, `translate`, `scale` and `rotate` (plus `color`, `background-color`, `border-color`, `text-decoration-color` for hover states, and `visibility` paired with opacity in `rise-in`). Keyframes move with `transform`; Tailwind's `translate-*`, `scale-*` and `rotate-*` utilities set the separate `translate`, `scale` and `rotate` properties, so a transition list names those, never `transform`. Nothing animates `height`, `width`, `margin`, `padding`, `top`, `left` or `box-shadow`, with one exception: a `<details>` opened or closed by the visitor grows and shrinks its content box (`::details-content` height to and from `auto`, R-MOT-06), because the shift it causes is the answer to their click (layout shifts within 500 ms of input do not count towards CLS) and a disclosure that snaps reads as broken; a hover shadow changes without a transition, and a shadow that must fade in does so by fading a pseudo-element that carries it.
- [ ] **R-MOT-03** Budget — At most three groups enter at once; a heading group, a grid row (its columns cascade 90 ms apart, so a four-column row finishes 270 ms after its first item) and a decorative depth layer each count as one, and a list cascades 70 ms per item for at most eight items. Entrance travel ≤ 64 px (the `expressive` item distance is 56 px), except the drawer, which slides its own width from the inline end. Depth (R-MOT-15): total travel ≤ 48 px per layer and at most two depth layers moving in any viewport. Durations from R-TOK-11 only. Nothing loops except `animate-pulse` on skeletons and `animate-spin` on a pending button.
- [ ] **R-MOT-06** Overlay entrances — Popovers use `motion-safe:transition-discrete motion-safe:transition-[opacity,translate,scale,display,overlay] motion-safe:duration-200 motion-safe:ease-out opacity-0 open:opacity-100 motion-safe:-translate-y-2 motion-safe:open:translate-y-0 motion-safe:starting:open:opacity-0 motion-safe:starting:open:-translate-y-2`; the drawer slides from the inline end (`translate-x-full` / `open:translate-x-0` / `starting:open:translate-x-full`). Dialogs use the same with `scale-95`/`open:scale-100`/`starting:open:scale-95` and `duration-300`, and their backdrop fades and blurs in (`backdrop:bg-ink/60 backdrop:backdrop-blur-sm backdrop:opacity-0 open:backdrop:opacity-100 starting:open:backdrop:opacity-0` with the same discrete transition).
- [ ] **R-MOT-07** Hover and focus — The hover vocabulary is fixed: buttons lift (`motion-safe:hover:-translate-y-px hover:shadow-md`), their trailing arrow nudges (`group-hover:translate-x-0.5 rtl:group-hover:-translate-x-0.5`) and they settle on press (`active:translate-y-0 active:scale-[0.98]`); cards lift 2 px and warm their border (`hover:-translate-y-0.5 hover:border-brand-300`, on the card's inner element, never on the wrapper that carries the entrance); link-style buttons and nav items grow an underline from the start edge (`after:` pseudo, `scale-x-0` → `hover:scale-x-100`, `origin-left rtl:origin-right`); disclosure chevrons rotate (`group-open:rotate-180`). Every transition is `motion-safe:transition-[color,background-color,border-color,translate,scale] motion-safe:duration-150` or narrower; the hover shadow (`hover:shadow-md`) changes without a transition (R-MOT-01). Hover never reveals content that is not reachable by keyboard or touch.
- [ ] **R-MOT-08** Header compaction — The header keeps its height; its shadow appears over the first 12 rem of scroll through a pseudo-element faded by a scroll-driven animation (`motion-safe:sda:after:animate-fade motion-safe:sda:after:[animation-timeline:scroll()] motion-safe:sda:after:[animation-range:0_12rem]`), never with a scroll listener. From the `standard` level the header also carries the reading-progress hairline: a one-pixel `before:` layer on the bar's bottom edge (`before:absolute before:inset-x-0 before:-bottom-px before:h-px`; absolute, because the bar's `backdrop-blur` makes it the containing block of fixed descendants anyway), `before:hidden` until `motion-safe:sda:before:block`, brand-to-accent gradient, `before:origin-left rtl:before:origin-right`, `motion-safe:sda:before:animate-progress motion-safe:sda:before:[animation-timeline:scroll(root)]`, on every page (it is the same information everywhere). It is a `motion-safe:` convenience: under reduced motion it is absent, because a progress bar in its final state would read as "done".
- [ ] **R-MOT-12** Carousels do not move by themselves — Scroll-snap carousels have no autoplay and no JS; scrolling is the only motion.
- [ ] **R-MOT-13** Smooth scrolling and back to top — `<html>` carries `motion-safe:scroll-smooth` so anchor links, the skip link and back-to-top scroll smoothly where motion is allowed. The footer's back-to-top link stays; a floating back-to-top button (`fixed bottom-6 end-6`, `size-11`, `#top` target) is rendered only under `sda:` support and appears through `rise-in` on a `scroll()` timeline over the first 60 vh, so it is invisible and unfocusable at the top of the page and present once the visitor has scrolled.
- [ ] **R-MOT-14** Scroll-driven appearance — Elements that appear or progress as the page scrolls (the floating back-to-top, the header shadow, the reading-progress hairline) use `animation-timeline: scroll()` with an explicit `animation-range` and a keyframe from R-TOK-13; they are rendered only under the `sda:` variant and have no script fallback, because they are conveniences, not content.
- [ ] **R-MOT-16** Entrance vocabulary — A grid item arrives with the treatment of its column, never a random one and never by index: three columns are slide-in (`start`, mirrored in RTL) / rise / framed settle (`settle`); four columns add slide-from-end (`end`) as the fourth; two columns are slide-in / slide-from-end; the columns of a row cascade 90 ms apart and the next row starts over. Tiles (team, integrations, awards) rise and their icon, avatar or badge pops (from the `expressive` level); steps all slide in from the start (a sequence reads along the writing direction) and their number badge pops; pricing tiers follow the column rule except that the recommended tier always settles; testimonial cards grow from 96 % (`scale`) in every column (a quote is a framed object, not a feature); article and media-row pictures settle from 115 % inside their frame (`zoom`); the bento follows the three-column rule with its lead always settling and its picture zooming; feature-index rows and spotlight points rise in sequence like a list (70 ms apart) while the spotlight picture slides in from the start and zooms; feature disclosures rise as one section (their panels move only when opened, R-MOT-06). The vocabulary applies from the `standard` level; `calm` rises everything.

### 07 Components

- [ ] **R-COMP-01** Anatomy template — Every catalog file begins with a comment block giving: name, purpose, anatomy (named parts), variants, states, spacing, motion, keyboard behaviour, a11y notes, i18n notes, content limits. A component without the block is not in the catalog.
- [ ] **R-COMP-02** States — Interactive components implement default, hover, focus-visible, active, disabled and (where data can be absent) loading, empty, error and success states, each shown on the style-guide page.
- [ ] **R-COMP-04** Sizes — Where a component has sizes they are `sm`, `md`, `lg` only; `md` is the default and the only size used in sections unless the anatomy block says otherwise.
- [ ] **R-COMP-05** Buttons — Variants: `primary`, `secondary`, `ghost`, `link`, `inverse`, `inverse-outline`. Classes include `group inline-flex items-center justify-center gap-2 min-h-11 px-5 rounded-md font-medium` plus the variant's colours, the focus ring and the hover vocabulary of R-MOT-07 (lift, press, arrow nudge). The primary and inverse variants end with the `arrow-right` icon unless `noArrow` is set; the icon mirrors in RTL. Labels are verb-first (bylaw 10) and never "Click here". Icon-only buttons have an `sr-only` label and `size-11`.
- [ ] **R-COMP-06** Links in components — Card titles are the card's link (`<a>` wrapping the heading text, with `after:absolute after:inset-0` on a `relative` card to make the whole card clickable). Link text is unique per page and describes the destination; "Read more" is allowed only as `<span aria-hidden="true">` decoration after a descriptive link.
- [ ] **R-COMP-08** Lists for repeated items — Repeated items (cards, logos, team members, nav links, tags) are `ul`/`li`; a single card is not wrapped in a list.
- [ ] **R-COMP-09** Overlays — Dropdowns, mega menus, the mobile drawer, tooltips and the locale switcher are `popover` elements opened by `button[popovertarget]` (light-dismiss and Escape are native). Modal content (video facade, gated download) is a `<dialog>` opened by `button[command="show-modal"][commandfor]` and closed by `<form method="dialog">`. Overlays never stack (R-LAY-12).
- [ ] **R-COMP-10** Disclosure — Accordions and FAQs are `<details name="<group>">` with a `summary` containing the heading text; an exclusive group shares one `name`. Tabs are the same element styled horizontally at `md` and above.
- [ ] **R-COMP-11** Carousel — A carousel is `<ul class="flex gap-6 overflow-x-auto snap-x snap-mandatory scroll-ps-4 ...">` with `snap-start` items, a visible scrollbar on hover, keyboard scrolling via the focusable items, no controls and no autoplay.
- [ ] **R-COMP-12** Facades — Third-party video and map embeds are facades: a poster image, a play or "Open map" button, and the iframe markup inside a `<dialog>` or `<template>` so no third-party request happens until the user acts; the facade states the provider and that it loads external content. Self-hosted video uses the `video` component: a native `<video controls playsinline preload="none">` with a generated poster in an `aspect-video` frame, MP4 and WebM sources from `/assets/video/`, and a visible title and duration beside it.
- [ ] **R-COMP-13** Icons — Icons come from the sprite allow-list in bylaw 17, sized `size-4` (inline), `size-5` (buttons, nav) or `size-6` (feature grids), always `aria-hidden="true"`.
- [ ] **R-COMP-15** Forms are built from primitives — Form components compose only the field primitives (input, select, textarea, checkbox, radio, switch, file) with the field wrapper that renders label, help text and error text per bylaw 16.

### 08 Sections

- [ ] **R-SEC-01** Section anatomy — A section is `<section class="py-16 md:py-24 bg-surface|bg-surface-alt" data-component="<name>">` containing the container, then an optional eyebrow, an `h2`, an optional lede, the body, and an optional single CTA. Order never changes.
- [ ] **R-SEC-10** Reveal eligibility — Reveal classes (R-MOT-05) go on sections below the fold and on grid items (staggered); never on the hero, page header, breadcrumbs or anything containing the `h1`.

### 10 Content

- [ ] **R-CONT-10** Microcopy keys — All UI strings (skip link, nav labels, button labels, form labels, help text, error messages, empty states, 404 copy, pagination, "opens in new tab") live in `engine/i18n/<locale>.json` under the keys listed in `engine/i18n/_template.json` and are used via the `t` filter. No UI string is typed into a template.
- [ ] **R-CONT-15** Empty and error copy — Empty states say what is missing and offer one action ("No open roles right now. Subscribe to job alerts."). Error messages say what went wrong and how to fix it, in one sentence, without blame ("Enter an email address like name@company.com").

### 14 Accessibility

- [ ] **R-A11Y-16** Status messages — Toasts and form status text live in a region with `aria-live="polite"` that exists in the DOM before the message appears.

### 15 Performance

- [ ] **R-PERF-05** Images — R-HTML-12 and D6: AVIF with WebP fallback in `<picture>`, `width`/`height`, `sizes` that matches the layout (`(min-width: 64rem) 50vw, 100vw` for split heroes, `(min-width: 48rem) 33vw, 100vw` for 3-column cards), lazy except the LCP image, which has `fetchpriority="high"` and is in the first 1 KB of body markup.

### 16 Forms

- [ ] **R-FORM-01** Method and destination — Forms use `method="get"` and `action="/<locale>/<form-slug>/thank-you/"`; the thank-you page reads nothing from the query string but exists for every form (R-PAGE-10). No form posts anywhere.
- [ ] **R-FORM-03** Control classes — Text-like controls use `block w-full min-h-11 rounded-md border border-line-strong bg-surface-raised px-3 text-base text-ink placeholder:text-ink-muted` plus the focus ring; invalid-after-interaction styling uses `user-invalid:border-danger-strong` only (never `invalid:`), and disabled uses `disabled:opacity-60 disabled:cursor-not-allowed`.
- [ ] **R-FORM-04** Native validation — Validation is native: `required`, `type` (`email`, `tel`, `url`), `minlength`/`maxlength`, `pattern` with a `title` explaining the format; `novalidate` is never set. Error copy follows R-CONT-15.
- [ ] **R-FORM-06** Error summary — The error state of a form shows the `error-summary` component before the first field: a heading "Fix the following", a list of links to each invalid field, and `tabindex="-1"` on the summary so it can receive focus. The catalog shows this state statically on the style-guide page.
- [ ] **R-FORM-08** Submit button — One `button type="submit"` per form, primary variant, verb-first label specific to the form ("Request a demo", "Send message", "Subscribe"). No reset buttons.
- [ ] **R-FORM-09** Spam control placeholder — Each form includes one honeypot text field inside a wrapper with `hidden`, `tabindex="-1"`, `autocomplete="off"` and `aria-hidden="true"`, named `website`; it is documented as the place a real deployment would add its anti-spam measure.
- [ ] **R-FORM-10** Consent and privacy text — Forms that collect personal data show a one-sentence privacy note with a link to the privacy page above the submit button; marketing opt-in is an unchecked checkbox with its own label; no pre-ticked boxes.
- [ ] **R-FORM-11** File upload — The file field states accepted types and maximum size in its help text and sets `accept`; the mock flow never uploads.
- [ ] **R-FORM-13** Layout — Fields stack with `space-y-6`; short related fields (postal code and city) sit in `grid md:grid-cols-2 gap-6`; labels sit above controls, never beside or inside them; placeholder text is an example, never the label.
- [ ] **R-FORM-14** Pending state — The submit button has a documented pending state (`disabled` plus spinner icon and "Sending…" text) shown on the style-guide page; it is never triggered in the mock because submission is a navigation.
