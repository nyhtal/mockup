# New site checklist

Use this once per site, from the Site Brief to the first green gate. It took the reference site (`sites/reference/`) about four commits; most of the time goes into the content data.

## Procedure

1. **Read the brief against `engine/site-brief/TEMPLATE.md`.** Every field has a destination file; a field the brief leaves empty takes the template's default. Decide the voice preset, the conversion, the locales (and which are RTL), the page tiers (core by default, optional by name) and the brand inputs.
2. **Create `sites/<name>/site.json`** from the brief: `name`, `tagline` (fallback; the localised one lives in the string overlay), `url`, `year`, `defaultLocale`, `locales`, `rtl`, `hasSearch`, `voice`, `contact`, `errorLinks`, `cta`, `nav`, `footer` (columns and legal), `brand` (`hue`, `accentHue`, `radius`, `density`, `motion`, `font`), `allowedExternal`. Labels are string keys, never text.
3. **Create the string overlay** `sites/<name>/i18n/<locale>.json` for every locale: nav labels and descriptions, footer column titles, `site.tagline`, site map group names, and any plural strings as objects of CLDR forms. Every locale must carry the same keys (`i18n/keys`).
4. **Create the data** `sites/<name>/data/<locale>/entities.json` and `pages.json` for every locale, same slugs everywhere. Start from the reference site's files and replace the content; keep every entity kind the recipes need. Descriptions are 120–155 characters in every locale (German runs about 35 % longer than English).
5. **Create the singular pages** `sites/<name>/content/<locale>/*.md` (front matter only; legal pages carry their markdown body with a "Last reviewed" `<time>`), plus `legal/imprint.md` for `de`.
6. **Write `sites/<name>/DECISIONS.md`**: the brief summary, the fictional-content statement, every override of a bylaw with rule ID, replacement, reason and date (R-PREC-02), and any third-party assets with their rights.
7. **Write `sites/<name>/glossary.json`** with the product and industry terms per locale.
8. **Build and gate**: `npm run build -- --site <name>` then `npm run gate -- --site <name> --skip lighthouse` while iterating; the full gate (with Lighthouse, several hours on a large site) before delivery. Fix findings in the data, never in the catalog.
9. **Run the checks in `pre-delivery.md`** and record them in `reports/latest.md`.

## Learned on the reference site

- The three-locale chrome (header, drawer, footer, switcher) costs about 27 KB per page; home pages with every optional section may exceed the HTML budget. Drop optional sections before touching the catalog.
- A German page with English UI strings is invisible to the gates: open one page per locale and read the chrome.
- A script font the brand font does not cover must be in the stack (`fontPlan` adds it); check that Arabic renders in Noto Sans Arabic, not in the Latin fallback.

## Rules this checklist verifies

Generated by `npm run checklists` from every rule whose `Gate:` line names `checklists/new-site.md`; edit the bylaws or the preamble in `_preambles/`, not this list. Tick each item or record the override in the site's `DECISIONS.md` (R-PREC-02; tier-1 rules cannot be overridden).

### 00 Precedence, overrides and the shape of a rule

- [ ] **R-PREC-02** Overrides are written down — A site may override a bylaw only by an entry in `sites/<name>/DECISIONS.md` giving the rule ID, the replacement rule, the reason and the date. An override of a tier-1 rule is not allowed.

### 02 Tokens

- [ ] **R-TOK-12** Motion presets — The brief's motion level sets three tokens: `calm` = distance 12px, duration 200ms, stagger 0; `standard` = 24px, 300ms, 60ms; `expressive` = 32px, 500ms, 90ms. Keyframes read them via `var(--reveal-distance)` and `var(--reveal-duration)`; nothing else changes.
- [ ] **R-TOK-14** Brand inputs from the brief — A site's `site.json` `brand` object provides only: `hue` (0–360), `accentHue`, `radius` (`sharp|soft|round`), `density` (`compact|comfortable`), `motion` (`calm|standard|expressive`), `font` (name from the approved list). The build writes these into the `@theme` block; nobody edits `app.css` per site.
- [ ] **R-TOK-15** Density — `density` only changes section padding (`comfortable` = `py-16 md:py-24`, `compact` = `py-12 md:py-16`) and card padding (`p-6` vs `p-4`). It changes no type sizes.

### 04 Typography

- [ ] **R-TYPO-01** Approved fonts — The brief's `font` is one of: `inter`, `figtree`, `ibm-plex-sans`, `source-sans-3`, `noto-sans`, or `system`. Arabic locales add `noto-sans-arabic`; the build only ships the files a site's locales need. Each is the variable `woff2` from `@fontsource-variable/<name>` (OFL 1.1); Latin faces ship as delivered, script faces are subset at build time to the script's core blocks and the weights the catalog uses (400–700), which takes the Arabic face from 166 KB to 53 KB so an Arabic page fits R-PERF-01.

### 09 Pages

- [ ] **R-PAGE-01** Tiers — Every page type is `core`, `optional` or `module`. A brief that says nothing gets every core page in every locale; optional pages are added by name; module pages come with their industry module.
- [ ] **R-PAGE-06** Legal pages — Privacy, cookies, terms, accessibility statement and (for `de`/`at` locales) the imprint exist on every site, carry a "Last reviewed" `<time>`, use the `prose` component and have no CTA band.

### 10 Content

- [ ] **R-CONT-01** Voice presets — The brief picks one voice: `plain` ("We build control software for factories."), `confident` ("Factories run better on Northwind."), or `warm` ("We help the people who keep factories running."). Every page's copy follows the chosen preset's sentence length (≤ 20, ≤ 14, ≤ 18 words on average) and person (we/you in all three).
- [ ] **R-CONT-11** Fictional, plausible, marked — Every company, person, customer, figure and quote is invented. Figures are plausible for the industry and never cite a real company, award body or regulator. Third-party platforms a product interoperates with (controller families, historians, engineering tools) may be named as compatibility facts only: never quoted, endorsed, given figures or made a customer. Each site's `DECISIONS.md` carries the line "All names, figures and quotes on this site are fictional."

### 14 Accessibility

- [ ] **R-A11Y-19** Accessibility statement — Every site ships `/legal/accessibility/` stating the conformance target, known gaps (none expected), the contact route and the review date.

### 17 Assets

- [ ] **R-ASSET-02** Naming — File names are lower-case kebab-case with a width suffix for raster images (`hero-automation-1200.avif`) and a content hash for fonts and CSS when the deployment adds one; no spaces, no uppercase, no dates in names.
- [ ] **R-ASSET-03** Icon sprite — Icons come from `lucide-static` (ISC, licence file copied to `engine/LICENSES.md`); `engine/tools/build-icons.js` builds a per-page sprite of `<symbol id="i-<name>">` elements from the allow-list in `engine/icons.json` (about 60 names); pages reference them per R-HTML-13. No other icon source.
- [ ] **R-ASSET-04** Fonts — Fonts are copied from `@fontsource-variable/<name>/files/` for the subsets a site's locales need (`latin`, `latin-ext`, `arabic`, …) into `/assets/fonts/`; `@font-face` declarations in `app.css` (exception list) use `font-display: swap`, `unicode-range` per subset and the metric overrides from R-TYPO-02. Licences (OFL 1.1) are recorded in `engine/LICENSES.md`.
- [ ] **R-ASSET-11** Theme colour — `<meta name="theme-color" content="<brand-600 light>" media="(prefers-color-scheme: light)">` and the dark counterpart are present; values are hex (not oklch) for browser support.
- [ ] **R-ASSET-12** Licences file — `engine/LICENSES.md` lists every third-party asset source (Lucide, each font) with licence name and link; a site's `DECISIONS.md` notes any brief-supplied asset and its rights.

### 18 Security and deployment

- [ ] **R-DEPLOY-08** No secrets, no PII — The repository and the build contain no credentials, API keys, real email addresses or real phone numbers; contact details are fictional and use reserved ranges (`example.com`, `+44 20 7946 0000`-style numbers).
