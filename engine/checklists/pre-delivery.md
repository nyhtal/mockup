# Pre-delivery checklist

Run this on the final build of a site, after the last content change. Its results are appended to `reports/latest.md` under a "Manual checks" heading, with the date, the commit and the name of the person who did them, after the last gate run (every gate run rewrites the file) (R-GATE-12). Budget half a day for a three-locale site.

## 1. The gates

- `npm run build -- --site <name>` then `npm run gate -- --site <name>`: all nine gates pass, `reports/latest.md` is regenerated and committed with the build's commit hash in its header. Lighthouse takes several hours on a large site (every default-locale page, one page per type in each other locale); run it last and unattended.
- `npm test` and `SMOKE=1 npm test` (against the built site) pass (R-GATE-11).
- The report's "Needs human review (axe incomplete)" list is read, not ignored. Items on `svg > text` (wordmarks, logo clouds) are covered by the theme's contrast check on the role tokens; anything else is checked by hand with a contrast tool.

## 2. Reflow and zoom (R-LAY-05, R-A11Y-19)

On one page per template, in every locale:

- 320 px wide: no horizontal scrolling, no clipped text, header fits, long headings wrap or hyphenate.
- 1024 px wide: the full header fits on one line, the CTA does not wrap.
- 400 % zoom at 1280 px: same checks.
- User text spacing (line height 1.5, paragraph 2×, letter 0.12em, word 0.16em): nothing clips.

## 3. Keyboard, screen reader and modes (R-A11Y-20)

On one page per template:

- Keyboard walk with no mouse: skip link first, visible focus on every control, popovers and the drawer open and close with Enter, Escape and outside click, focus returns to the trigger.
- Screen-reader read (NVDA on Windows) of header, hero, one section and footer: landmarks named, headings in order, the current page announced in the nav and the locale switcher.
- RTL locale: the wordmark reads left to right, arrows and chevrons mirror, the drawer opens from the end edge, text aligns start.
- Dark scheme, Windows High Contrast, reduced motion, print preview: readable, boundaries visible, nothing hidden.

## 4. Structured data (R-SCH-13)

One page per type in Google's Rich Results Test and the Schema Markup Validator: no errors; warnings noted.

## 5. Content

- Native-speaker proofread of every locale is done and recorded in the site's `DECISIONS.md` (who, when).
- The fictional-content statement is in `DECISIONS.md`; no real customer, person, award body or regulator is quoted or given figures.
- Every form's thank-you page is reached by submitting the form in the browser pane.

## 6. Deliverable

- `dist/<name>/` copied to a clean folder opens from its root with the headers and redirects files applied by the host; `404.html`, `500.html`, `sitemap.xml`, `robots.txt`, `feed.xml` per locale and `.well-known/security.txt` are present.
- `reports/latest.md` records the gate table, the Lighthouse coverage table, the page weights and the manual checks above.

## Rules this checklist verifies

Generated by `npm run checklists` from every rule whose `Gate:` line names `checklists/pre-delivery.md`; edit the bylaws or the preamble in `_preambles/`, not this list. Tick each item or record the override in the site's `DECISIONS.md` (R-PREC-02; tier-1 rules cannot be overridden).

### 00 Precedence, overrides and the shape of a rule

- [ ] **R-PREC-01** Precedence order — When two rules or a rule and a brief conflict, the higher tier wins: (1) legal and accessibility, (2) performance, (3) validation, (4) consistency bylaws, (5) site brief look-and-feel.
- [ ] **R-PREC-05** Bylaw versioning — The bylaw set carries a semver version in `engine/CHANGELOG.md`. A change that makes a previously green site fail a gate is a major version; a new rule with a new gate is minor; wording is patch. The reference site is rebuilt and gated on every bump.
- [ ] **R-PREC-07** The CSS exception list — `engine/theme/app.css` contains only: `@import "tailwindcss"`, `@source` lines, one `@theme` block (with its `@keyframes`), `@custom-variant` lines, named `@utility` blocks for the R-COL-09 backgrounds (`bg-hero-backdrop`: layered gradients and a mask that no utility can express) and for the item distance of R-TOK-12 (`reveal-items`: sets `--reveal-distance` to the item value on a grid, with its `md` media query), `@font-face` blocks for the site's fonts, and the `@view-transition` block wrapped in `@media (prefers-reduced-motion: no-preference)`. No `@apply`, no `@layer components`, no selectors, no inline `style`.
- [ ] **R-PREC-09** Research before rules — A rule that depends on a browser feature, a Lighthouse audit, a validator message or a Google policy cites its source URL in the file and is re-checked when the bylaws' major version changes. *(SHOULD)*

### 02 Tokens

- [ ] **R-TOK-06** Brand scales are generated — `brand-*` and `accent-*` are OKLCH scales generated from the brief's hue: lightness 97, 93, 86, 76, 66, 56, 48, 40, 33, 26, 20 for steps 50–950, chroma rising from 0.02 at the ends to 0.17 at 500–600. `brand-600` is the primary action colour and must reach 4.5:1 on `surface`.

### 03 Layout

- [ ] **R-LAY-07** Sticky header — The header is `sticky top-0 z-10` with a fixed height of `h-16`, and `<html>` carries `scroll-pt-20` so everything scrolled into view (anchor targets and keyboard focus alike) clears the header (WCAG 2.4.11). No per-target `scroll-mt-*` is needed.
- [ ] **R-LAY-11** Print — Header navigation, footer navigation, popovers, dialogs, decorative media and motion are `print:hidden`; prose prints with `print:text-black`; links in prose show their URL via content utilities only where the bylaw for prose allows.
- [ ] **R-LAY-12** Stacking order of overlays — Only one overlay is open at a time: opening a dialog closes popovers; the mobile drawer is a popover and closes on navigation.

### 05 Colour

- [ ] **R-COL-03** Contrast — Text on its background reaches 4.5:1 (3:1 for text ≥ 24px or ≥ 19px bold); UI boundaries and focus indicators reach 3:1 against adjacent colours. This holds in both schemes.
- [ ] **R-COL-04** Focus ring — Every interactive element carries `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-focus` and nothing removes the outline. `focus` (without `-visible`) is not styled.
- [ ] **R-COL-06** Never colour alone — Every meaning carried by colour (error, selected, current, required) is also carried by text, an icon or an underline.
- [ ] **R-COL-10** Forced colours — Components rely on borders or outlines, not background colour alone, for boundaries so they survive Windows High Contrast (`forced-colors: active`); icons use `currentColor`. *(SHOULD)*

### 06 Motion

- [ ] **R-MOT-04** Content is visible without motion — An entrance may hide an element only in its `pending:` state, and `pending:` (`engine/theme/app.css`) matches only on screen, with `prefers-reduced-motion: no-preference`, after `enhance.js` has set `data-js`, and until the script marks the element `data-revealed`. Without JavaScript, with reduced motion and in print the page renders final states. Elements already above 88 % of the window when the script starts are marked before `pending:` can apply. Text is never hidden by any other means (no word-by-word fades, no clip reveals).
- [ ] **R-MOT-09** Page transitions — Cross-document view transitions are enabled by the exception-list block `@media (prefers-reduced-motion: no-preference) { @view-transition { navigation: auto; } }`. No element gets a `view-transition-name` except the header (`[view-transition-name:header]`), so only content cross-fades.

### 07 Components

- [ ] **R-COMP-14** Touch targets — Every control is at least 24×24 CSS px with 24 px spacing to the next target; buttons and nav links are ≥ 44 px tall.
- [ ] **R-COMP-16** Style-guide page — Every site ships `/<default locale>/style-guide/` (noindex) showing every primitive, component variant and state in use on that site, built from the same catalog.

### 09 Pages

- [ ] **R-PAGE-07** Error pages — `404.html` and `500.html` exist at the output root and per locale, use the base shell, offer search and three top links, and reference nothing that could itself fail (no facades, no forms).
- [ ] **R-PAGE-08** Root redirect — `/index.html` at the output root is a valid page that sends the visitor to the default locale with `<meta http-equiv="refresh" content="0; url=/<default>/">` and a visible link; it carries `noindex`.
- [ ] **R-PAGE-09** Style guide — `/<default locale>/style-guide/` exists with `noindex` and shows every catalog entry used on the site (R-COMP-16). It is built once, in the default locale, because its sample data is English; the locale coverage check exempts it, and the site's own pages show the chrome in every other locale.
- [ ] **R-PAGE-12** Noindex set — These pages carry `<meta name="robots" content="noindex">` and are excluded from the sitemap: root redirect, style guide, thank-you pages, search results, tag archives, 404, 500, maintenance, coming soon. Lighthouse's SEO category is not scored for them (its is-crawlable audit fails by design); the other three categories still must reach 100 (R-GATE-10).

### 11 Internationalisation

- [ ] **R-I18N-15** Sitemap alternates — `sitemap.xml` lists each page once per locale with `xhtml:link rel="alternate" hreflang` entries mirroring the page's head.

### 12 SEO and metadata

- [ ] **R-SEO-03** Robots — `<meta name="robots" content="noindex">` appears only on the pages in R-PAGE-12; indexable pages carry no robots meta. `robots.txt` allows everything and names the sitemap.
- [ ] **R-SEO-04** Open Graph — Every page has `og:type` (`website` for home, `article` for posts and news, `website` otherwise), `og:title` (page title without site suffix), `og:description` (the meta description), `og:url` (canonical), `og:site_name`, `og:locale` (`en_GB`-style from the locale), `og:locale:alternate` per other locale, and `og:image` with `og:image:width` 1200, `og:image:height` 630 and `og:image:alt`.
- [ ] **R-SEO-05** Twitter card — `twitter:card` is `summary_large_image`; `twitter:title`, `twitter:description` and `twitter:image` repeat the OG values.
- [ ] **R-SEO-06** Social image — Each page's social image is generated at build time (bylaw 17): 1200×630, brand gradient, page title and site name in a system sans-serif (the renderer cannot load the site's web font), no photos; the home page uses the site's tagline as its title.
- [ ] **R-SEO-07** Sitemap — `sitemap.xml` at the root lists every indexable page in every locale with `lastmod` (ISO date) and hreflang alternates (R-I18N-15); pages in R-PAGE-12 are excluded.
- [ ] **R-SEO-08** Feed — Sites with a blog or news section publish `feed.xml` (Atom) per locale at `/<locale>/feed.xml`, linked from the head of index and post pages with `<link rel="alternate" type="application/atom+xml">`.
- [ ] **R-SEO-10** Internal linking — Every page is reachable within three clicks from the home page; every detail page links to its index and to three related items; the footer links to every core page group.
- [ ] **R-SEO-12** security.txt and humans — `/.well-known/security.txt` exists with `Contact`, `Expires` (one year ahead) and `Preferred-Languages` lines; `humans.txt` is not shipped.

### 13 Structured data

- [ ] **R-SCH-11** Escaping — The JSON is emitted with `<`, `>` and `&` escaped as `\u003c`, `\u003e` and `\u0026` so no content can close the script element.
- [ ] **R-SCH-13** Validation — The schema gate passes on every page, and before delivery one page per type is checked in Google's Rich Results Test and the Schema Markup Validator; results are noted in `reports/latest.md`.

### 14 Accessibility

- [ ] **R-A11Y-01** Conformance target — Every page meets WCAG 2.2 Level AA. Automated checks are a floor; the manual list in R-A11Y-20 is the ceiling.
- [ ] **R-A11Y-03** Focus visible, never obscured — The focus ring in R-COL-04 is present on every control, and no sticky element (header, sub-nav, toast, cookie banner) can cover a focused element: `<html>` carries `scroll-pt-20` (R-LAY-07) so focus scrolling clears the header.
- [ ] **R-A11Y-05** Dialogs — Modal dialogs open with `showModal()` (via `command="show-modal"` or the script fallback), put `autofocus` on the first meaningful control, close on Escape (native), close via `<form method="dialog">` button labelled "Close", and return focus to the trigger (native).
- [ ] **R-A11Y-06** Popovers — Popover triggers are `button[popovertarget]`; the popover's first child is focusable content or a heading; light dismiss and Escape are native; the trigger shows the open state via the `open:` variant on a `has-[:popover-open]` parent or `aria-expanded` where unavoidable (R-HTML-08).
- [ ] **R-A11Y-07** Target size and spacing — Controls meet R-COMP-14 (≥ 24 px, ≥ 44 px for buttons and nav); inline links in prose are exempt per WCAG 2.5.8.
- [ ] **R-A11Y-08** Contrast — R-COL-03 contrast ratios hold in both colour schemes and over media (R-COL-08); axe measures `oklch()` colours; the contrast items it still marks incomplete (text over gradients, images or overlays it cannot resolve) are listed in `reports/latest.md` and checked by hand.
- [ ] **R-A11Y-09** Motion — R-MOT-02 (all motion under `motion-safe:`), no autoplay (R-MOT-12), no flashing content.
- [ ] **R-A11Y-11** Redundant entry and consistent help — Multi-step forms carry entered values forward (GET parameters) so nothing is asked twice; the contact link sits in the same footer position on every page.
- [ ] **R-A11Y-17** Reflow and text spacing — Pages reflow at 320 px and 400 % zoom (R-LAY-05) and remain readable with user text spacing (line height 1.5, paragraph 2×, letter 0.12em, word 0.16em) because no container clips text.
- [ ] **R-A11Y-18** Pointer alternatives — Nothing requires drag, hover or multi-point gestures; carousels scroll by keyboard and by touch; tooltips are also reachable by focus.
- [ ] **R-A11Y-20** Manual checks — Before delivery, on one page per template: keyboard walk with no mouse; screen-reader read (NVDA on Windows) of header, hero, one section, footer; 400 % zoom; RTL locale visual check; Windows High Contrast; reduced-motion; print preview. Results are recorded in `reports/latest.md`.

### 15 Performance

- [ ] **R-PERF-04** Fonts — At most two font files per page (one per script); the primary file is preloaded with `crossorigin`; `font-display: swap` plus metric overrides (R-TYPO-02); subsets per locale; the `system` option ships none.
- [ ] **R-PERF-10** Benchmark conditions — The gate records Lighthouse version, Chrome version, Node version, OS, commit, throttling profile and run count in `reports/latest.md`; numbers without conditions are not reported.
- [ ] **R-PERF-11** Caching and compression — The deployment serves `/assets/` with `Cache-Control: public, max-age=31536000`, adding `immutable` only when the host gives asset names a content hash, and Brotli or gzip for text; `engine/tools/serve.js` sends the hash-free form so the gate sees it. *(SHOULD)*
- [ ] **R-PERF-14** Analytics placeholder — No analytics or tag manager ships. A single HTML comment `<!-- analytics: add after consent; see bylaw 18 -->` marks the place before `</body>`.
- [ ] **R-PERF-16** Rerun on change — Any change to the catalog, theme or script reruns the full gate on the reference site before merge.

### 16 Forms

- [ ] **R-FORM-07** Preserved input — Multi-step forms pass values forward as GET parameters and prefill via `value` attributes at build time for the mock flow; nothing already entered is asked again (R-A11Y-11).

### 17 Assets

- [ ] **R-ASSET-10** Social images — `/assets/og/<page-slug>.png` (1200×630, PNG for platform compatibility, ≤ 150 KB) generated per page with the brand gradient, page title and site name; `og:image:alt` is "{Page title} · {Site name}".

### 18 Security and deployment

- [ ] **R-DEPLOY-01** Headers file — The build emits `_headers` (Netlify/Cloudflare syntax) and `headers.json` (generic) with: `Content-Security-Policy: default-src 'self'; img-src 'self' data:; style-src 'self'; script-src 'self'; font-src 'self'; connect-src 'self'; frame-src 'none'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'; upgrade-insecure-requests`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=()`, `Strict-Transport-Security: max-age=31536000; includeSubDomains`, and the asset cache rule from R-PERF-11.
- [ ] **R-DEPLOY-02** JSON-LD under CSP — The JSON-LD block needs no CSP exception because browsers do not execute `application/ld+json`; the policy above has no `'unsafe-inline'`.
- [ ] **R-DEPLOY-03** Facades and CSP — When a facade loads a third-party iframe after a click, the site's `DECISIONS.md` lists the provider origin to add to `frame-src`; the shipped CSP stays `frame-src 'none'` until then.
- [ ] **R-DEPLOY-04** Error pages — `/404.html` and `/500.html` exist at the output root (R-PAGE-07), and the deployment maps 404 and 5xx to them; the static server used by the gate does the same for 404.
- [ ] **R-DEPLOY-05** Redirects — `_redirects` (and `redirects.json`) map `/` → `/<default-locale>/` (301 where the host supports it; the root HTML page from R-PAGE-08 covers hosts that do not), non-slash URLs to slash URLs, and nothing else.
- [ ] **R-DEPLOY-06** Discovery files — The root contains `robots.txt` (allow all, sitemap line), `sitemap.xml`, `.well-known/security.txt`, and the favicon set; nothing else at the root except the redirect page and error pages.
- [ ] **R-DEPLOY-07** Staging is not indexed — Staging deployments send `X-Robots-Tag: noindex` from the host configuration; the build never bakes `noindex` into indexable pages.
- [ ] **R-DEPLOY-09** Cookies and consent — The mockup sets no cookies and uses no storage, so no consent banner is shown; the `consent-banner` and `consent-preferences` components exist in the catalog with the rule: "enable when the first non-essential cookie or tracker is added, and gate that script behind consent". Video and map facades count as consent-requiring on click and say so.
- [ ] **R-DEPLOY-10** Output is the deliverable — `dist/<site>/` is a complete, self-contained folder: copying it to any static host with the headers and redirects applied is the whole deployment. The build is reproducible from a clean checkout with `npm ci && npm run setup && npm run build -- --site <name>`.

### 19 Quality gates

- [ ] **R-GATE-01** The command — A site is gated with `npm run build -- --site <name>` followed by `npm run gate -- --site <name>`; the gate exits non-zero on any failing check and writes `reports/latest.md`.
- [ ] **R-GATE-11** Unit tests — `npm test` (Node's test runner over `engine/tools/test/*.test.js`) passes; browser-driven gate tests run with `SMOKE=1 npm test` against a built site.
- [ ] **R-GATE-12** Manual checklist — `checklists/pre-delivery.md` is completed and its result recorded in `reports/latest.md`, including the R-A11Y-20 checks, the R-SCH-13 Rich Results check and the R-LAY-05 reflow check.
- [ ] **R-GATE-13** Planned checks — The following checks are referenced by bylaws but implemented in a later phase; until then they are covered by the manual checklist: `budget/contrast` (token-level contrast ratios in both schemes), `consistency/motion-props` (R-MOT-01), `consistency/url-policy` (R-PAGE-02), `consistency/canonical` (R-SEO-02), `consistency/no-hardcoded-strings` (R-CONT-10). Role colours need no check: the theme wipes Tailwind's palette, so a palette class fails `consistency/class-exists`. They are added as the catalog phase makes their inputs stable. *(SHOULD)*
